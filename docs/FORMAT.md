# Формат файлов FNIRSI 2C53T

Исследование выполнено на 9 парах BIN+BMP из репозитория
[RafaelDiasCampos/FNIRSI-2C53T-Decoder](https://github.com/RafaelDiasCampos/FNIRSI-2C53T-Decoder)
(коммит 88cafe9, 2026-07-13). Прибор сохраняет пару файлов при снимке экрана: `N.bin` и `N.bmp`.

## BIN (607 байт)

| Смещение | Размер | Содержимое | Статус |
|---|---|---|---|
| 0x000 | 301 | CH1, экранные отсчёты, uint8 | подтверждено (BMP) |
| 0x12D | 301 | CH2, экранные отсчёты, uint8 | подтверждено (BMP) |
| 0x25A | 1 | флаги каналов: бит 0 — CH1, бит 1 — CH2 | подтверждено (BMP, 9/9) |
| 0x25B | 4 | uint32 **big-endian** = 301 (число отсчётов) | вероятно; во всех файлах `00 00 01 2D` |

Данные **выключенного** канала в файле присутствуют (остатки прежних данных) и не отображаются.

### Что означает байт отсчёта

Отсчёт — это вертикальная координата луча на экране 320×240, а не код АЦП:

* экранная строка = `248 − код`; код 228 — верхняя линия сетки, 28 — нижняя, 128 — центр;
* 25 кодов на деление, 8 делений по вертикали → разрешение 1/25 деления;
* отсчёт `i` нарисован в столбце `9 + i`; 25 отсчётов на деление, 12 делений, 301 точка.

Проверка: каждый декодированный отсчёт найден точно на пикселе луча (`x = 9+i`, `y = 248−код`)
во всех 9 снимках: 301/301 для одиночных каналов; для двух каналов — 297/301 (лучи
перекрываются), для образца 5 77 отсчётов CH2 закрыты надписями «Freq/Duty/Vp-p» и не учитываются.

### Чего в BIN нет

В/дел, время/дел, положение нуля канала (смещение), множитель щупа, вход AC/DC, триггер.
Без них доступны только «деления от центра экрана» и «номер отсчёта».

### Перевод в физические единицы

```
шаг отсчётов, с   = (время/дел) / 25
напряжение, В     = (код − код_нуля) / 25 × (В/дел)
```

* В/дел — значение, **показанное на экране** (оно уже учитывает щуп X10): для образца 1
  «20V X10», размах 90 кодов → 3,6 дел × 20 В = 72 В, прибор показывает Vp-p 72,67 В.
* Шаг = время/дел ÷ 25 (а не 12·время/дел ÷ 301, как в исходном проекте): сигнал 1 кГц
  при этом даёт 1000,0 Гц, при второй формуле получилось бы 1003 Гц.
* Частота экранных отсчётов не равна частоте АЦП прибора; спектр выше её половины не виден.

## BMP (153 654 байт)

320×240, 16 бит RGB565, строки сверху вниз (высота в заголовке отрицательная).

* **Метка нуля** канала — треугольник у левого края цвета канала (CH1 `0x7F40`, CH2 `0x02BF`),
  высотой 9 пикселей. `код_нуля = 248 − строка центра метки` (точность ±1 код). Проверено на
  DC-сигнале 0…3 В (образец 3: нижний уровень = 0,0 В) и на AC-сигналах (среднее ≈ 0).
* **Надписи шкал**: «H=200uS» вверху, «500mV» (цвет канала) и «X10 DC» внизу. Шрифт сглажен
  с дробным позиционированием, поэтому распознаётся сравнением с шаблонами
  (`src/fnirsi2c53t/decoders/glyph_templates.py`, генератор `tools/build_glyphs.py`) с допуском и
  проверкой однозначности. Проверка «без своего снимка»: 43 из 45 полей верно, 2 отказа,
  0 ложных прочтений.
  Известные символы: верх `0 1 2 = H S m u`, низ `0 1 2 5 A C D V X m`. Символы, которых нет в
  образцах (например «5» в «H=500uS», «n» в «nS»), дают «не распознано» → ввод вручную.
* Шкалы из BMP применяются, только если отсчёты BIN совпали с лучом на снимке (≥ 90 %).

# FNIRSI 2C53P (927 байт, проверено на 3 парах с прибора)

BIN лежат в `Screenshot simple file\N.bin`, снимки — в `Screenshot file\N.bmp` (480×272, строки снизу вверх).

| Смещение | Размер | Содержимое | Статус |
|---|---|---|---|
| 0x000 | 461 | CH1, экранные отсчёты uint8 | подтверждено (458/461 на луче) |
| 0x1CD | 1 | максимум CH1 | совпадает с отсчётами 3/3 |
| 0x1CE | 1 | минимум CH1 | совпадает 3/3 |
| 0x1CF | 461 | CH2 | по аналогии; CH2 был выключен во всех образцах |
| 0x39C / 0x39D | 1+1 | макс./мин. CH2 | у выключенного CH2 — устаревшие значения |
| 0x39E | 1 | флаги каналов | 0x01 = только CH1 |

Экран: столбец = 9 + i, строка = 270 − код; 50 пикселей на деление по горизонтали, 32 — по вертикали
(сетка 9,2 × 7,5 деления), центр = код 120. Шаг отсчёта = время/дел ÷ 50.
Надписи: чёткий пиксельный шрифт, известные символы `0 1 2 A C S V X m`.

На медленных развёртках (200 мс/дел) прибор не дорисовывает луч до конца: в BIN 461 отсчёт, на экране
меньше. Программа находит это по снимку и предупреждает, что хвост, вероятно, состоит из старых данных.

**Не проверено:** CH2 включённым (цвет луча берётся со снимка), значения 5 и n/u/k в надписях.

# FNIRSI 2C23T (только снимки экрана)

Прибор сохраняет только `img_NN.bmp` (320×240, строки сверху вниз), данных осциллограммы нет.
Программа **оцифровывает луч**: на каждый столбец берётся центр пикселей луча (CH1 `0x0296` синий,
CH2 `0x7DC0` жёлто-зелёный). Сетка: столбцы 10…310, строки 18…218, 25 пикселей на деление, центр — строка 118
(код = 246 − строка). Строки 178–214 (надписи Vavg/Vpp/Freq) исключаются, пропуски заполняются линейной
интерполяцией с предупреждением. Метки нуля: CH1 `0x039F`, CH2 `0x6D80`.

Проверка на 6 снимках: все шкалы распознаны (`500ns`…`500us`, `20mV`…`1V`). Частота совпадает с прибором
в пределах 1,5 % (1 кГц; 11,07 кГц против 11,11). Размах на 2–10 % ниже показаний прибора: острые вершины
теряются при оцифровке по центру штриха.

# FNIRSI 1013D (поддерживается, исходная прошивка FNIRSI)

Файлы: `N.wav` (15 000 байт, это не звуковой WAV) и `N.bmp` (800×480 RGB565). Снимок (SAVE PIC) и данные
(SAVE WAVE) сохраняются разными кнопками и нумеруются независимо; при одинаковом номере кадры могут
различаться, если прибор был в RUN. Формат разобран Robert Tidey
(github.com/roberttidey/FNISR1013DScope) и W. Voigt (github.com/wavoigt/FNIRSI-1013D-WAV-Viewer-in-Excel-VBA,
учёт смещения нуля); их алгоритм переписан на Python (`decoders/fnirsi_1013d.py`) и проверен на
21 файле с прибора пользователя.

| Байты | Содержимое |
|---|---|
| 2 / 12 | канал показан (CH1 / CH2) — выведено по 21 файлу, совпадает со снимками |
| 4 / 14 | индекс В/дел: 5; 2,5; 1; 0,5; 0,2; 0,1; 0,05 В, × щуп |
| 8 / 18 | вход 0 DC, 1 AC |
| 10 / 20 | щуп 10^n (X1, X10, X100) |
| 22 | развёртка 0…29: 50 с … 10 нс (1-2-5) |
| 26 / 28 / 30 | триггер: режим / фронт / канал |
| 84 / 86 | uint16: значение буфера, соответствующее 0 В (положение луча) |
| 208…303 | измерения прибора (кодировка разобрана не полностью, не используются) |
| 1000 / 4000 | буфер CH1 / CH2: 1500 × uint16 |
| 7000 / 8500 | экранные точки CH1 / CH2: 750 × uint16, строка = 449 − значение буфера |

* Напряжение = (отсчёт − ноль) / 50 × В/дел; шаг по времени = развёртка / 50 (буфер = 30 делений).
* Экранные 750 точек — точное окно буфера (смещение 355–406 в образцах); на снимке точка i — столбец 3 + i,
  строка 448 − значение. На растянутых/медленных развёртках окно не находится — программа предупреждает.
* Проверка: файл 1 — 3,24 В / 1,000 кГц (экран прибора 3,17 В / 1,00 кГц); метка нуля CH1 на снимке
  в строке 212 = 449 − 237 (значение из байтов 84–85); точки CH2 совпали со снимком на 700 из 723.
* Альтернативные прошивки (Peco V0.0005, Atlan V0.26d) имеют другую раскладку: такие файлы отклоняются
  с сообщением, а не читаются неверно. Поддержку можно добавить по алгоритму W. Voigt, когда будут образцы.
